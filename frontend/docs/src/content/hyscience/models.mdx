HYscience is model-agnostic. A **model** is one inference endpoint the agent routes through; a **provider** is a vendor that exposes models. Routing happens on your machine: with your own keys (the default), each call goes straight from your machine to the provider — no gateway in the middle, no account required.

## Bring your own keys

Set a key from any provider and start working:

```bash
hyscience
```

Keys stay on your machine. Any connected HY model source works the same way. You can also paste keys into the Credentials panel in the [workspace](/hyscience/workspace), and a subscription can sign in without a key.

## List what is configured

```bash
hyscience models             # grouped by source, with a routing label per source
hyscience models <source>    # one source
```

Each source is labeled `your key`, `managed`, `signed in with a subscription`, or `unconfigured`, so you always know which route a model takes. `--verbose` adds per-model metadata like costs, `--refresh` refetches the catalogue, and `--flat` prints one `source/model` id per line for scripting.

## Pick a model per run

```bash
hyscience run --variant high "Design the ablation study"
hyscience run "Clean up the plotting code"
```

`--model <source>/<model>` overrides the default for one run; in the workspace, use the model selector per session. `--variant` picks a reasoning-effort tier — `minimal`, `high`, `max`, and so on. Available tiers depend on the model.

## HYcloud managed (optional)

```bash
hyscience login   # defaults to app.hyscience.ai
hyscience wallet  # balance and key routing
hyscience status  # connection state
hyscience logout  # disconnect
```

| Path | What runs where | Billing |
| --- | --- | --- |
| BYOK (default) | Your machine calls the provider directly. | Your provider account. |
| HYcloud managed | Your machine calls HYcloud, which calls the provider. | Prepaid wallet. See [Connect to HYcloud](/hyscience/cloud). |

## Key hygiene

Provider keys and synced credentials are filtered out of the environment of every subprocess the agent spawns and redacted from output. The agent talks to providers itself; the code it runs never needs your keys. Credentials are stored per user in your home directory, never in the project's `.hyscience/` directory, so they cannot end up in a commit. See [Security](/hyscience/security).
